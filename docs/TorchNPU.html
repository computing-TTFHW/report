  2. #2
    11 个字段
    id
    P2-config-key-conflict
    severity
    high
    category
    runtime-regression
    title
    源码构建的 torch_npu 2.13.0 与 torch 2.13.0+cpu 存在 config key 冲突，import 崩溃
    description
    源码树 torch_npu/csrc/core/npu/NPUAllocatorConfig.h:139 的 getKeys() 注册了 `pinned_reserve_segment_size_mb`，而 torch 2.13.0 的 c10/core/AllocatorConfig.h:273 也注册了同名 key。torch_npu 动态库加载时调用 registerDeviceConfigParserHook 触发 `Duplicated key` ValueError，import 直接 SIGABRT (exit 134)。
    evidence
    源码构建 wheel: import 失败 exit 134；PyPI 发布的 torch_npu==2.13.0rc1: import 成功且 NPU 操作正常。说明冲突是源码树相对 rc1 的回归（rc1 的 getKeys() 未含此 key 或 torch 2.13.0 后续新增了此 key）。
    root_cause
    torch_npu 源码 getKeys() 包含 `pinned_reserve_segment_size_mb`，与 torch 2.13.0 libc10.so 中已注册的同名 key 冲突
    workaround
    使用 PyPI 发布的 torch_npu==2.13.0rc1 可正常 import 和运行；或从 getKeys() 移除该 key（需源码修改，超出验证范围）
    file
    torch_npu/csrc/core/npu/NPUAllocatorConfig.h
    line
    139
    status
    open
