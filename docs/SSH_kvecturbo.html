文档缺失 (5)

#1high

CMakeLists.txt 中 -lsecurec 位于源文件 kvecturbo.o 之前，导致静态库 libsecurec.a 符号(memcpy_s)未被提取。构建产物 libkvecturbo.so 中 memcpy_s 为未定义符号(UND)，外部程序直接链接会报 undefined reference to memcpy_s。UT 正常是因为 test/ut_test/CMakeLists.txt 的链接顺序正确(-lsecurec 在后)。

分类: 链接顺序缺陷
说明
CMakeLists.txt 中 -lsecurec 位于源文件 kvecturbo.o 之前，导致静态库 libsecurec.a 符号(memcpy_s)未被提取。构建产物 libkvecturbo.so 中 memcpy_s 为未定义符号(UND)，外部程序直接链接会报 undefined reference to memcpy_s。UT 正常是因为 test/ut_test/CMakeLists.txt 的链接顺序正确(-lsecurec 在后)。
建议
在 CMakeLists.txt 顶层构建中调整链接顺序：将 target_link_options 中的 -lsecurec 移到 target_link_libraries 并通过 target_link_libraries(kvecturbo PRIVATE ... securec) 链接，或使用 ${BINARYLIBS}/kernel/platform/Huawei_Secure_C/comm/lib/libsecurec.a 显式链接
#2medium

仓库无独立样例程序。README quick_start.md 仅说明需对接 openGauss DataVec 数据库使用，初学者无法单独验证库功能。

分类: 样例缺失
说明
仓库无独立样例程序。README quick_start.md 仅说明需对接 openGauss DataVec 数据库使用，初学者无法单独验证库功能。
建议
在 docs 或 examples 目录提供独立 C++ 样例，展示 VectorArray 初始化、PQ 编码、GetPQDistance 调用，便于不装数据库即可验证
#3low

test/ut_test/test.sh 依赖 lcov/genhtml 生成覆盖率报告，但 openEuler 22.03 官方仓库无 lcov 包，脚本会在此步骤失败。

分类: 覆盖率工具缺失
说明
test/ut_test/test.sh 依赖 lcov/genhtml 生成覆盖率报告，但 openEuler 22.03 官方仓库无 lcov 包，脚本会在此步骤失败。
建议
在文档中说明 lcov 需从源码安装（如 pip install lcov）或降级为可选步骤
#4low

安装指南使用 "yum install gcc g++ cmake libgomp make"，但 openEuler 中 C++ 编译器包名为 gcc-c++（g++ 不是独立包），yum/dnf 会报 No match for argument: g++。

分类: yum 命令包名问题
说明
安装指南使用 "yum install gcc g++ cmake libgomp make"，但 openEuler 中 C++ 编译器包名为 gcc-c++（g++ 不是独立包），yum/dnf 会报 No match for argument: g++。
建议
将文档命令改为 "yum install gcc gcc-c++ cmake libgomp make"
#5low

README 目录结构提到 test 目录为 ut测试，但未在 README 或安装指南说明如何执行单元测试（实际为 cd test/ut_test && sh test.sh）。

分类: 文档未说明 UT 执行方式
说明
README 目录结构提到 test 目录为 ut测试，但未在 README 或安装指南说明如何执行单元测试（实际为 cd test/ut_test && sh test.sh）。
建议
在安装指南增加 UT 执行章节

documentation_gaps
  1. #1
    4 个字段
    category
    链接顺序缺陷
    description
    CMakeLists.txt 中 -lsecurec 位于源文件 kvecturbo.o 之前，导致静态库 libsecurec.a 符号(memcpy_s)未被提取。构建产物 libkvecturbo.so 中 memcpy_s 为未定义符号(UND)，外部程序直接链接会报 undefined reference to memcpy_s。UT 正常是因为 test/ut_test/CMakeLists.txt 的链接顺序正确(-lsecurec 在后)。
    severity
    high
    suggestion
    在 CMakeLists.txt 顶层构建中调整链接顺序：将 target_link_options 中的 -lsecurec 移到 target_link_libraries 并通过 target_link_libraries(kvecturbo PRIVATE ... securec) 链接，或使用 ${BINARYLIBS}/kernel/platform/Huawei_Secure_C/comm/lib/libsecurec.a 显式链接
